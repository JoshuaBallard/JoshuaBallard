# Josh Ballard

I spent a decade in IT infrastructure. VMware, Linux, security, operations, mostly in defense and aerospace.

The job taught me one thing above everything else: never trust a system that reports it's fine.

Lately I've been building with AI, and that instinct turned out to matter more than anything else I brought to it.

## What I've built

**[Built in a Day](https://joshuaballard.github.io/built-in-a-day/)** · [repository](https://github.com/JoshuaBallard/built-in-a-day)

A product built in one afternoon instead of a job application. Twelve chapters, twenty-two pull requests, every commit timestamped. Static HTML, CSS, and vanilla JavaScript. No build step, no dependencies. Chapter six is four failures that all reported success first.

**Ballard's Platform** (private)

Started as a private Minecraft server for my family. Became Docker services, an API, a custom Java plugin, a world atlas, and a set of engineering standards an AI coding agent has to work inside. The standards exist because it printed a live token into a session once.

**[Quiet Wells](https://quietwells.com/landing)**

Capture sermon notes, connect ideas across time, and actually revisit them. What it taught me is that context beats perfect transcription. Handwriting is messy, but surrounding context recovers meaning.

**[Dad Mode](https://dadmode.thedaduprising.com/welcome)**

An AI coach for busy dads. I made the coach too harsh and six dads told me so. Rewriting his operating instructions fixed the product faster than any feature would have.

## What I think about building with AI

- Context matters more than clever prompting.
- Documentation is shared memory.
- A passing test can still test the wrong thing.
- Verification matters more than confidence.
- AI didn't lower the bar for building software. It raised the bar for judgment.

I'm not the most experienced engineer in this space. I'm reasonably good at finding the real problem, and at saying plainly when something didn't work.
